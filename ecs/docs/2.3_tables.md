# 2.3 A table

`ecs/src/2.components/2.3.tables/tables.rin`

The two halves meet. Part 1 built the entity index: handles, slots, packed
rows, swap-remove. 2.1 and 2.2 built the component side: ids, a registry,
columns of bytes. A **table** is 1.4's packed rows with the typed arrays
replaced by columns, one per component in its signature:

```
table {position velocity health}
  entities  [ 0:1 | 3:1 | 2:1 | ... ]     who owns each row
  columns   position [ ... ]  velocity [ ... ]  health [ ... ]
  count, capacity                         shared by every column
```

Row `r` is entity `entities[r]`, and its components are row `r` of every
column. This world still has a single table, so every entity has the same
components; 2.4 gives each combination its own.

## Step 1: the table

```rin
kayan_table: struct = {
    signature: u64;
    count: u64;
    capacity: u64;
    entities: ^kayan_entity;
    columns: [64]kayan_column;
}
```

- `signature` says which components the table has.
- `columns[id]` is in use when the signature has bit `id`. The rest stay
  zeroed. 64 slots indexed by id means finding a column is an index, never a
  search. kayan in C looked columns up by name in a hash map, which is the
  thing this replaces.
- `count` and `capacity` belong to the table, shared by every column and by
  `entities`, so they can't disagree.

A table is made from a signature and the registry:

```rin
kayan_table_init: proc(w: *kayan_world, signature: u64) -> kayan_table = {
    t: kayan_table = {};
    t.signature = signature;
    for (id: u32 = 0; id < 64; id += 1) {
        if ((signature & kayan_bit(id)) != 0) {
            if (id >= w*.component_count || w*.infos[id] == null) {
                printfmt("kayan: signature {} uses component {}, which was never registered\n", signature, id);
                exit(1);
            }
            t.columns[id] = kayan_column_init(w*.infos[id]);
        }
    }
    return t;
}
```

The signature *is* the column list. In your C kayan, the signature and the
columns were written separately and could disagree (archetype `D` had
position columns its signature didn't mention). Here one is made from the
other.

## Step 2: rows, for every column at once

Adding a row grows every column together when the table is full, then zeroes
the new row in each:

```rin
kayan_table_add_row: proc(w: *kayan_world, t: *kayan_table, e: kayan_entity) -> u64 = {
    if (t*.count == t*.capacity) {
        kayan_table_grow(w, t);
    }
    row: u64 = t*.count;
    t*.count += 1;
    t*.entities[row] = e;
    for (id: u32 = 0; id < w*.component_count; id += 1) {
        if (kayan_table_has(t, id)) {
            kayan_column_zero_row(t*.columns[id]&, row);
        }
    }
    return row;
}
```

Removing a row is 1.4's swap-remove, for every column:

```rin
kayan_table_remove_row: proc(w: *kayan_world, t: *kayan_table, row: u64) -> void = {
    last: u64 = t*.count - 1;
    if (row != last) {
        for (id: u32 = 0; id < w*.component_count; id += 1) {
            if (kayan_table_has(t, id)) {
                kayan_column_copy_row(t*.columns[id]&, row, last);
            }
        }
        moved: kayan_entity = t*.entities[last];
        t*.entities[row] = moved;
        vec<kayan_slot>at(w*.slots&, cast(moved.index, u64))*.row = cast(row, u32);
    }
    t*.count = last;
}
```

Compare it with 1.4's `kayan_despawn`: the same moves and the same slot fix,
but over columns of bytes instead of named arrays. This proc works for any
table that will ever exist.

## Step 3: the typed view of a table

```rin
kayan_slice: proc<T>(t: *kayan_table) -> []T = {
    id: u32 = kayan_id_of<T>();
    if (!kayan_table_has(t, id)) {
        printfmt("kayan: the table has no column for component {}\n", id);
        exit(1);
    }
    return kayan_column_slice<T>(t*.columns[id]&, t*.count);
}
```

`kayan_slice<position>(t)` is the table's position column as a `[]position`,
cut to the rows in use. Systems will live on this in Part 3: get the slices,
loop over rows.

## Step 4: the world

```rin
kayan_world: struct = {
    arena: *memops_arena;
    infos: [64]*const reflect;
    component_count: u32;
    slots: vec<kayan_slot>;
    free: vec<u32>;
    live: u64;
    table: kayan_table;
}
```

The registry from 2.1, the slots and free list from Part 1 (as `vec`s now, so
the 8-entity limit is gone), and one table. Spawning is Part 1's spawn with
the row coming from the table:

```rin
    e.generation = slot*.generation;
    slot*.row = cast(kayan_table_add_row(w, w*.table&, e), u32);
    w*.live += 1;
    return e;
```

and despawning is Part 1's despawn calling `kayan_table_remove_row`.

## Step 5: writing a new entity's data

There's no typed `get` or `set` yet (that's 2.5), so the program finds the
row and writes through the column slices:

```rin
        row: u64 = kayan_row(w&, drones[i]);
        ps: []position = kayan_slice<position>(w.table&);
        vs: []velocity = kayan_slice<velocity>(w.table&);
        hs: []health = kayan_slice<health>(w.table&);
        ps[row] = { .at = { .x = 10.0 * cast(i, f32), .y = 0.0 } };
```

## Run it

```
spawned 6 drones into one table; it grew from 4 rows to 8
    6 rows, room for 8
    row 0  0:1  position ( 0.00,  0.00)  health 100
...
despawn 0:1 and 3:1
    4 rows, room for 8
    row 0  5:1  position (50.00,  0.00)  health 100
    row 1  1:1  position (10.00,  0.00)  health 100
    row 2  2:1  position (20.00,  0.00)  health 100
    row 3  4:1  position (40.00,  0.00)  health 100
spawn 3:2: a reused number, the next row, zeroed except what we set
...
kayan_verify: 0 problems
```

Row 0 went to `5:1` (the last row moved into the hole), then row 3 went to
`4:1` the same way. Every column moved together, and the slots followed.
